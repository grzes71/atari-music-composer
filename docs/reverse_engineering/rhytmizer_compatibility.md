### 1.2 Corrected `AUDCTL ($D208)` Hardware Semantics & Channel Allocation Analysis

In real POKEY hardware (`CO12294` datasheet / `atari800` / `ASAP 8.0.0` / `src/atari_music/pokey_hw.py`):
- **Bit 0 (`$01`, `AUDCTL_15KHZ`):** Switches POKEY's shared base-clock prescaler from `64 kHz` (`CPU ÷ 28` = `63,337.39 Hz` PAL) to `15 kHz` (`CPU ÷ 114` = `15,556.55 Hz` PAL).
- **Bit 1 (`$02`, `AUDCTL_HIPASS_CH2_CH4`):** Enables the High-Pass Filter on Channel 2 clocked by Channel 4 (it is **not** a clock selector for Channels 3 and 4).
- **Bit 5 (`$20`, `AUDCTL_CH3_179MHZ`) and Bit 6 (`$40`, `AUDCTL_CH1_179MHZ`):** Disconnect Channel 3 (or joined 16-bit `CH3+CH4` when Bit 3 `$08` is also set) and Channel 1 (or joined 16-bit `CH1+CH2` when Bit 4 `$10` is also set) from the shared `64 kHz / 15 kHz` base-clock prescaler and clock them directly from the **`1.773447 MHz` PAL CPU clock**.

This yields five concrete rules for Atari Music Composer channel allocation:
1. **Which channels are used by Rhytmizer?** Rhytmizer writes only to **Channels 1 and 2** (`$D200–$D203`) plus `AUDCTL ($D208)`. Channels 3 and 4 (`$D204–$D207`) are never touched by Rhytmizer.
2. **Effect of `AUDCTL` Bit 0 (`$01`) on Channels 3 and 4:**
   - If Channels 3 and 4 operate in **standard 8-bit base-clocked mode** (`AUDCTL` Bits 5 and 3 = `0`), setting `AUDCTL = $01` switches their base clock from `63.34 kHz` to `15.56 kHz` along with Channels 1 and 2. They can still play 8-bit melodic notes from **`30.5 Hz` (`AUDF=$FE`, ~B0) to `972 Hz` (`AUDF=$07`, ~B5)** without hardware conflict provided the exporter/compiler compiles CH3/CH4 note frequencies using `audctl = 0x01` (`hz_from_audf_8bit(audf, audctl=0x01)`).
   - If Channels 3 and 4 operate as a **joined 16-bit pair clocked at 1.79 MHz (`AUDCTL = $28`, or `$29` with Bit 0 set)**, **CH3+CH4 is clocked from the 1.77 MHz CPU clock and is 100% unaffected by `AUDCTL` Bit 0 (`$01`)** — allowing CH1 and CH2 to run at the 15 kHz base clock while CH3+CH4 plays high-precision 16-bit melody/bass with zero frequency change.
3. **Can CH1 and CH2 be reserved for percussion while CH3 and CH4 handle melody?**
   - **Yes:** `player.asm` v2 updates all four channels (`X = 0..3`) symmetrically every VBI frame. Reserving CH1 (`$80` noise layer) + CH2 (`$A0` tonal sweep layer) for dual-channel percussion leaves CH3 and CH4 free for two independent 8-bit melodic tracks.
4. **What does the current `POKEYRuntime` / `player.asm` architecture permit without code changes?**
   - `player.asm` v2 already supports any static song-wide `audctl_mode` byte in the song header (`$00`, `$01`, `$50`, etc.) and any channel assignment of 8-bit instruments with `TransientMacroSpec` and `PitchEnvelopeSpec`.
   - However, `player.asm` v2 does **not** dynamically rewrite `AUDCTL ($D208)` mid-song per note. Therefore, in an unmodified `player.asm` v2 song, all instruments in the arrangement must share a single `effective_audctl` (normally `$00` for 8-bit 64 kHz arrangements, or `$50` when CH1+CH2 is locked to 16-bit bass).

## 2. Mathematical Frequency Conversion Analysis (`AUDCTL=$01` → `AUDCTL=$00`)

Because the PAL base-clock divisor ratio is $\frac{114}{28} = \frac{57}{14} \approx 4.071429$, converting a 15 kHz divider $N_{15}$ to a 64 kHz divider $N_{64}$ via:
$$N_{64,\text{ideal}} = (N_{15} + 1) \times \frac{57}{14} - 1$$
never yields an integer unless $(N_{15} + 1)$ is a multiple of 14. Consequently, **none of the converted `AUDF` values below are mathematically exact**; every in-range value is a nearest-integer approximation, and every value with $N_{15} \ge 63$ (`$3F`) exceeds the 8-bit maximum (`$FF = 255`, or `$FE = 254` in the tracker format where `$FF` is reserved as `END_OF_TRACK`).

> [!WARNING]
> **Why `$C0` (`poly4`) Is NOT a Timbral Equivalent for `SPACE>BASS DRUM` or `6>TOM 3`:**
> Although distortion `$C0` (4-bit polynomial LFSR, 15-tick period) can reach `70–120 Hz` fundamentals under `AUDCTL = $00` (64 kHz), it replaces Rhytmizer's clean `50%` square-wave drum body (`$A0` pure tone) with a buzzy, asymmetric 15-bit pulse sequence rich in upper harmonics. Any `$C0`-based 64 kHz profile must be treated as a **synthetic substitute**, whereas faithful reproduction of `SPACE>BASS DRUM` and `6>TOM 3` requires `AUDCTL` Bit 0 (`$01` 15 kHz base clock) or 16-bit channel joining.

## 3. Four-Mode Compatibility Evaluation (Modes A, B, C, D)

For each instrument we distinguish four implementation modes:
- **Mode A (`Original 2-Channel Sub-Frame`):** `rhytmizer.xex` native execution (`CH1 + CH2`, `140 Hz` blocking loop, per-instrument `AUDCTL` `$00`/`$01`, `12–24` cycle `$1F/$1B` DAC pop).
- **Mode B (`Single-Channel 50 Hz Approximation`):** 1 channel (`CH4`) in `player.asm` v2 (`core_v2_iter1`), `AUDCTL = $00` (64 kHz), 50 Hz VBI (`20.0 ms`/frame) using `TransientMacroSpec` / `PitchEnvelopeSpec`.
- **Mode C (`Dual-Channel 50 Hz Synthesis`):** 2 simultaneous channels (`CH1+CH2` or `CH3+CH4`) in `player.asm` v2 (`core_v2_iter1`) at 50 Hz VBI (`20.0 ms`/frame), evaluated under:
  - **Mode C1 (`AUDCTL = $00`, 64 kHz):** Standard 64 kHz base clock across all 4 channels.
  - **Mode C2 (`AUDCTL = $01` or `$29`, 15 kHz base clock):** Native 15 kHz base clock on the 2 percussion channels (with melodic channels either compiled for 15 kHz 8-bit `AUDCTL=$01` or running in 16-bit 1.79 MHz mode `AUDCTL=$29`).
- **Mode D (`Dedicated Sub-Frame Playback`):** Custom `~140–150 Hz` (`3×` per PAL frame via DLI / POKEY Timer IRQ) dual-channel percussion driver with per-instrument `AUDCTL` (`$00`/`$01`).

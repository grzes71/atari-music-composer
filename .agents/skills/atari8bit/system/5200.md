# Atari 5200 SuperSystem

> **When to load:** The task involves Atari 5200 porting, memory maps,
> controller/keypad input, cartridge layout, or code that assumes XL/XE
> register addresses.
> **Do not use for:** Ordinary Atari 400/800/XL/XE programs unless the user
> explicitly targets the 5200.
> **Source note:** This file is self-contained.

## 1. Differences From Atari 8-Bit Computers

The 5200 shares the 6502 CPU family and several custom chips with the
400/800 computer line, but software is not binary-compatible without
porting. The 5200 has no keyboard, no PIA, no normal SIO use in the base
console, a different cartridge model, relocated GTIA and POKEY addresses,
and a much smaller OS ROM.

| Area | Atari 400/800/XL/XE | Atari 5200 |
|---|---|---|
| RAM | Commonly 16K-64K plus expansions | 16K at `$0000-$3FFF` |
| Cartridge | 8K windows at `$8000-$9FFF` and/or `$A000-$BFFF`, plus CCTL `$D500-$D5FF` | 32K cartridge area at `$4000-$BFFF`; no CCTL region |
| GTIA | `$D000-$D0FF` | `$C000-$CFFF` |
| ANTIC | `$D400-$D4FF` | `$D400-$D4FF` |
| POKEY | `$D200-$D2FF` | `$E800-$EFFF` |
| PIA | Present on computers | Not present |
| OS ROM | Larger OS ROM with vectors and services | 2K kernel ROM at `$F800-$FFFF`; `$F000-$F7FF` is unused ROM space |
| RNMI reset line | Used by 400/800 reset behavior | ANTIC exists, but RNMI is not attached |

The 5200 power system uses cartridge lines so the console is not normally
running without a cartridge inserted.

## 2. Memory Map

| Range | 5200 use |
|---|---|
| `$0000-$3FFF` | 16K RAM |
| `$4000-$BFFF` | 32K cartridge area |
| `$C000-$CFFF` | GTIA |
| `$D400-$D4FF` | ANTIC |
| `$E800-$EFFF` | POKEY |
| `$F000-$F7FF` | Unused ROM area |
| `$F800-$FFFF` | 2K kernel ROM and character font |

ANTIC display programming is broadly familiar, but any code that writes GTIA
or POKEY through computer-line addresses must be retargeted. There is no
PIA `PORTA/PORTB`, so XL/XE banking and 400/800 joystick-port assumptions do
not apply.

## 3. Controllers

The standard controller has an analog stick, top and bottom fire buttons,
a numeric keypad with `0-9`, `#`, `*`, and Start/Reset/Pause buttons. Consoles
may expose two or four controller ports.

### Analog Stick

The analog stick uses POKEY `POTx` lines:

- Even `POT` lines are horizontal axes.
- Odd `POT` lines are vertical axes.
- Lower horizontal values mean left; higher horizontal values mean right.
- Lower vertical values mean up; higher vertical values mean down.
- The analog stick does not auto-center. Software should calibrate a center,
  often between waves/levels by measuring or averaging expected rest values.
- A healthy controller is expected to have at least about 160 counts of
  side-to-side range on the corresponding `POTx` register.
- `CONSOL` bit 2 must be set for analog joystick reads. Clearing it cuts
  power to the potentiometers, causing `POTx` to read the maximum value
  (`$E4`). The same line is also used for trackball calibration/detection.

### Keypad and Console Buttons

The keypads are multiplexed through POKEY keyboard scanning. Low two bits of
`CONSOL` select which controller to read:

| `CONSOL` bits 0-1 | Controller |
|---|---|
| `00` | controller 1 |
| `01` | controller 2 |
| `10` | controller 3 |
| `11` | controller 4 |

The selected controller's keypad and Start/Pause/Reset buttons appear in
`KBCODE` bits 1-4:

| Button | Code bits |
|---|---|
| `1` | `1111` |
| `2` | `1110` |
| `3` | `1101` |
| Start | `1100` |
| `4` | `1011` |
| `5` | `1010` |
| `6` | `1001` |
| Pause | `1000` |
| `7` | `0111` |
| `8` | `0110` |
| `9` | `0101` |
| Reset | `0100` |
| `*` | `0011` |
| `0` | `0010` |
| `#` | `0001` |

The K0 and K5 output lines are unused, so POKEY sees each pressed key more
than once during a scan. Disable keyboard debounce (`SKCTL` bit 0 clear) to
detect keypad presses; if debounce remains enabled, redundant mappings can
look like multiple pressed keys and suppress reporting. When debounce is
disabled, held keys are reported repeatedly at the keyboard scan rate.

### Triggers

- Bottom fire buttons are wired to `TRIG0-TRIG3`, one per controller.
- The top fire button is wired through POKEY keyboard logic and appears like
  SHIFT/CONTROL/BREAK activity. It can set the BREAK IRQ bit and can affect
  high bits of `KBCODE` when a keypad key is pressed.

## 4. Porting Rules

- Replace computer GTIA `$D0xx` addresses with 5200 `$C0xx`.
- Replace computer POKEY `$D2xx` addresses with 5200 `$E8xx`.
- Remove PIA/PORTB banking logic; the 5200 has no PIA and no XL/XE extended
  memory window.
- Do not depend on CIO keyboard/editor services from the computer OS.
- Rework input around analog calibration, keypad multiplexing through
  `CONSOL`, and POKEY keyboard scan behavior.
- Cartridge code can assume a 32K cartridge region at `$4000-$BFFF`; do not
  use `$D500-$D5FF` CCTL bank-switch assumptions from Atari computer carts.
